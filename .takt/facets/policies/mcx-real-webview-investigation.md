# 実 WebView 調査ポリシー

X の実 DOM に依存するロジックを、合成 DOM のテストだけで完了扱いにせず、実 DOM の事実に基づいて計画・検証する。

## 原則

| 原則                             | 基準                                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| 発動条件を先に判定               | 下記の発動条件に該当するかを最初に判定し、判定結果をレポートに残す                        |
| 合成 DOM を実 DOM の証拠にしない | jsdom のテストが通っても、実 X での動作の証拠として扱わない                               |
| 計画段階で事実を集める           | 実 DOM の構造・セレクタ・タイミング・実測値を調べ、計画に事実として残す                   |
| 完了前に実 DOM で再確認する      | 実装後、完了前に実 DOM で動作を確認し、結果をレポートに残す                               |
| 推測を事実として書かない         | 実機で確認していない項目は「未確認」と明記する                                            |
| 実アプリ固有条件は実アプリで見る | カラムの寸法などは Chrome 拡張だけでは再現できないため、実アプリの WebView で確認する     |
| 副作用を起こさない               | 調査で JS の alert / confirm 等のダイアログを発火させず、投稿・フォロー等の実操作をしない |
| 恒久知見は残す                   | 今後も使える新知見は `docs/development/inject-ipc-shortcuts-notes.md` に追記する          |

## 発動条件

| 条件                                                                                               | 判定   |
| -------------------------------------------------------------------------------------------------- | ------ |
| `src-tauri/src/inject/_src/**` を新規作成・変更する                                                | 発動   |
| X の実 DOM 構造に依存するロジック（セレクタ、React fiber、仮想リスト、スクロール位置など）に触れる | 発動   |
| 上記のいずれにも触れない（Rust 単体、設定 UI、React 画面のみ、ドキュメントのみ等）                 | 対象外 |

対象外の場合は調査・検証を省略してよい。省略した場合は、レポートに「実DOM調査: 対象外（理由）」と書く。

## 発動時の義務

| 段階     | 義務                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 計画     | 実 DOM を調査し、判明した事実（セレクタ、DOM 構造、タイミング、実測値）を計画に残す。既存知見は `docs/development/inject-ipc-shortcuts-notes.md` を先に確認し、重複調査を避ける |
| 実装後   | `npm run build:inject` 後、完了前に実 DOM で動作を再確認する。確認した内容、手段、結果（実測値を含む）をレポートに残す                                                          |
| 完了報告 | 実 DOM で確認できなかった項目は「未確認」として理由とともに列挙する                                                                                                             |

## 調査手段

手段は 2 系統。計画段階と完了前の確認でどちらを使うかを、レポートに残す。

### 1. 実 X サイトを Chrome で調べる

`claude-in-chrome` MCP が使える場合に使う。

| 基準                                                                                             | 判定                                               |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `claude-in-chrome` が使えない、または使えない理由を確認できない状況で、実 X を確認したと報告する | REJECT                                             |
| 使えない場合に、実アプリ CDP（下記 2）へ切り替える、またはユーザーへの確認が必要と報告して止まる | OK                                                 |
| タブが背面（`visibilityState: hidden`）のまま仮想リスト・スクロール系を計測する                  | REJECT（仮想リストが描画されず計測が不正確になる） |
| 調査用タブを前面にしてから計測する                                                               | OK                                                 |
| ログイン済みアカウントが必要な画面を、未ログインのまま確認したと報告する                         | REJECT                                             |
| ログインが必要な場合にユーザーへ確認が必要と報告する                                             | OK                                                 |
| 調査中に JS の alert / confirm 等のダイアログを発火させる操作をする                              | REJECT（ブラウザ操作が止まる）                     |

### 2. 実アプリの WebView を CDP で調べる

カラムの寸法（例: 高さ 1424px）など実アプリ固有の条件は、Chrome 拡張だけでは再現できないため、この手段で確認する。

| 手順          | 内容                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 起動          | `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=0 --remote-allow-origins=*"` を付けて `npm run tauri:dev` する |
| ポート取得    | `%APPDATA%\com.natsuyasai.multicolumnx\accounts\<id>\EBWebView\DevToolsActivePort` の 1 行目がポート                           |
| 接続          | `http://127.0.0.1:<port>/json` へ CDP で接続する                                                                               |
| inject 変更後 | `npm run build:inject` を実行すると、開発起動中のアプリが再ビルドされる                                                        |

| 基準                                                                                         | 判定                                                                          |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| リモートデバッグポートを 9222 等に固定する                                                   | REJECT（アカウントごとに別の WebView2 環境が起動し、最初の 1 つしか取れない） |
| `--remote-debugging-port=0` とし、アカウントごとの `DevToolsActivePort` からポートを取得する | OK                                                                            |
| 実アプリで確認する前提のスクロール距離・寸法を、Chrome の寸法だけで決める                    | REJECT（取得に必要な距離はビューポート高さに依存し、固定値ではない）          |

## 判定基準

| 基準                                                                                    | 判定   |
| --------------------------------------------------------------------------------------- | ------ |
| inject 変更なのに、発動条件の判定結果がレポートにない                                   | REJECT |
| 発動条件に該当するのに、計画に実 DOM の事実（セレクタ・構造・タイミング・実測値）がない | REJECT |
| 発動条件に該当するのに、実装後の実 DOM 再確認結果がレポートにない                       | REJECT |
| 発動条件に該当するのに、jsdom のテスト結果だけを動作確認の根拠にしている                | REJECT |
| 実 DOM の事実が、確認した手段と結果を伴わず記述されている                               | REJECT |
| 実 DOM の確認ができなかった理由と未確認項目が明記されている                             | OK     |
| 対象外の場合に「実DOM調査: 対象外（理由）」がレポートにある                             | OK     |
| 恒久的な新知見を `docs/development/inject-ipc-shortcuts-notes.md` へ追記している        | OK     |
