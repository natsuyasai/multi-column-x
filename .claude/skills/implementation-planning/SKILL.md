# 実装指示書の作成（フェーズ2）

確定した仕様（EARS と Gherkin）を元に、**実際に作業するエージェント向けの指示書**を作る。人は読まない。読みやすい説明・体裁・要約は不要で、迷わず正確に実行できることだけを基準にする。**人の確認・承認は求めない。**

## 進め方

1. **設計**: 要求を満たす実装方針を設計する。既存の関数・ユーティリティ・パターンを優先して再利用し、新規追加は最小限にする。対象シンボルの定義・呼び出し元・影響範囲・関連テストはまず CodeGraph で確認する。`gap-analysis.md` と、変更領域の `docs/development/*-notes.md` を読む。必要なら `Plan` サブエージェントで設計を検証する。
2. **設計観点の検討**: 変更が複数ファイル・複数モジュールにまたがる、または非自明な設計判断を伴う場合は、[references/design-review-perspectives.md](references/design-review-perspectives.md) の観点を検討し、該当する対応だけを指示書に反映する。
3. **案の決定**: 内部実装の複数案はエージェントが決め、採用理由を指示書に1行で残す。**利用者に見える振る舞いが案で変わる場合は決めずに**、仕様（フェーズ1.2）に戻ってユーザーに確認し、確定し直す。
4. **出力**: 対象ごとの専用フォルダに出力する（git管理外）。出力したら、そのままフェーズ3へ進む。

## 一時ドキュメントの仕様

- 作業フォルダ: `tmp/plans/<日付>-<対象名>/`（例: `tmp/plans/2026-06-23-column-reorder/`）
- 計画ファイル: 上記フォルダ内の `plan.md`（例: `tmp/plans/2026-06-23-column-reorder/plan.md`）
- このフォルダにはフェーズ3で `progress.md`（進捗）も出力する。**計画と進捗は必ず同一フォルダに配置すること。**
- `tmp/` はgit管理外（`.gitignore` 済み）
- 別セッションが単独で実装を再開できる粒度で記述する。冒頭に承認モードと `session.md` の内容（ブランチ戦略・PR作成の要否）、仕様2ファイルの絶対パスを書く
- **フェーズ3を委譲される Sonnet サブエージェントが単独で実行できる詳細度で書く**（CLAUDE.md「サブエージェント運用」）。具体的には: 自己完結（会話文脈を前提にしない）／現状コードの引用／変更後のコード断片／正確なファイルパス／落とし穴チェックリスト
- コミット末尾のトレーラー（`Co-Authored-By` / `Claude-Session`）をプランに明記する（委譲プロンプトにそのまま転記し、サブエージェントごとの表記ゆれを防ぐ）

### 記載項目

- **目的**: 満たす要求（仕様ファイルのパスと、各ステップが担う要求番号）
- **対応方針**: 採用するアプローチと理由
- **変更対象**: 主要な変更ファイルと、再利用する既存関数・パターン（パス付き）
- **プラットフォーム影響**: desktop / mobile / Android のどれに影響するか。Rust の `#[cfg(desktop)]` / `#[cfg(mobile)]` 分岐、inject スクリプト、serde 命名、ProGuard keep ルールへの波及有無
- **作業分割**: コミット単位に分けた作業ステップ（各ステップでTDDを回す前提）
- **テスト方針**: 確定した `docs/specs/<機能名>.feature`（フェーズ1.5〜1.7）の全シナリオを、`@unit`（単体テスト）/ `@integration`（結合テスト・Storybook play function等）/ `@manual`（フェーズ6で手動テスト項目化）のどれで担保するかを割り当てる。シナリオ名の一覧と割当先テストファイルを記載し、割当漏れがないこと。**Gherkin由来のテストを「TDD（Red先行）」と「実装後作成」のどちらで進めるかも明記する**（実装後作成でもコミット前のミューテーション確認は必須）。これに加えて Storybookカタログ / プロパティテスト を作るかを記載する（Gherkin対象外のリファクタ・docs・CI変更のみの場合は「Gherkin対象外」と明記）
- **対応方針（設計観点）**: 設計観点の検討で該当した項目（2-1〜2-11）とその対応方針
- **完了基準と検証方法**: format / lint / test / build を含む確認手順、および設計観点の検討で該当した完了基準項目（1-1〜1-5）

## 完了条件

- 確定した仕様の全要求が作業ステップに、全シナリオがテストレベル（単体/結合/手動）に割り当てられている
- `tmp/plans/` に、エージェントが単独で実行できる指示書が出力されている

出力したらフェーズ3（`subagent-tdd-implementation`）へ進む。

## 禁止事項

- 指示書の人手レビューや着手の承認を求めること
- 利用者に見える振る舞いを、仕様に無いまま指示書で決めること
- 指示書を一時ドキュメントに残さず実装に進むこと
