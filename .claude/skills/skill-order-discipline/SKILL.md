# スキルの手順遵守

`.claude/skills/` に定義された順序付き手順（フェーズ・ステップ）は、**すべてのステップを定義された順番通りに実行する**。

## 基本ルール

- 手順の途中で作業を打ち切り、ユーザーに「次に何をしますか」と尋ねてはならない。定義された次のステップへそのまま進める
- ステップの一部をスキップしてよいのは、**ユーザーから明示的にスキップの指示があった場合のみ**
- スキルが定義する確認ポイント（ユーザー承認待ち等のゲート）は手順どおりに待つ。それ以外の箇所で独自に確認を差し込んで手順を止めない

## 適用対象

このプロジェクトの `.claude/skills/` 配下にある、順序付きフェーズ・ステップを持つスキル全般に適用する。例:

- `feature-development-flow`（フェーズ1〜6）
- `subagent-tdd-implementation`（委譲 → コミット → レビューの実装サイクル）
- `refactor` / `tdd`（Phase 1〜4 / Red-Green-Refactor）
- `check-creation`（検証コマンドの実行順序）

## 具体例

- `feature-development-flow` のフェーズ3実装中に、ステップごとに「次はプロパティテストを作りますか？」と確認を挟むことは禁止。フェーズ4の適用要否判断まで手順どおりに進める
- `check-creation` の途中でエラーが出ても、そこで報告して終わりにせず、修正してから手順の続き（次のチェック）まで実行する

## 例外

- ユーザーが「〇〇は今回スキップしてください」等、明示的にステップの省略を指示した場合はそのステップを飛ばしてよい
- スキル自体が「ユーザー承認を得るまで次に進まない」と定義しているゲート（例: `clarify-requirements` の要求確定、`implementation-planning` のプラン確定）は手順どおりに承認を待つ。これは「手順を飛ばす」ことには当たらない

## 禁止事項

- 手順の途中で独自判断により中断し、ユーザーに次のアクションを尋ねること
- スキルが定義していない箇所で確認を差し込み、手順の完了を遅らせること
