# リリース前確認項目一覧

リリースのたびに確認する項目の一覧。リリース時はこの一覧の全項目で試験を実施し、項目と結果をリリース PR（develop → main、タイトル `v<version>`）の本文に記載する（手順は `.claude/skills/pre-release-test`）。

## 0. この一覧の運用

- この一覧は「常に確認する項目」だけを記載する。**結果・実施日・実施回数・対象バージョンなどの試験記録は書かない**（記録はリリース PR に書く）
- 更新するのは項目の追加・削除と、項目の内容（観点・事前条件・操作手順・期待結果・優先度・実施者）の修正だけ
- 機能追加・挙動変更・バグ修正の PR で、次回以降のリリースでも確認が必要な観点はその PR で項目を追加する。漏れはリリース時に `pre-release-test` が補う
- No. は再採番しない。削除した項目の No. は欠番とし、再利用しない（過去のリリース PR の結果表が No. で項目を参照するため）。新しい項目は各プレフィックス（X / W / A / L / C）の最大番号の次を使う
- 由来 PR は項目を追加したきっかけの PR。項目は一度追加したら、機能の削除などで不要になるまで常設の確認項目として扱う

## 1. 環境と凡例

### 試験環境

| 環境    | 内容                                                        | 実施者                       |
| ------- | ----------------------------------------------------------- | ---------------------------- |
| Windows | Windows 11、リリースビルド（`npm run tauri:build`）         | 自動試験（人が補う項目あり） |
| Android | エミュレータ Pixel_9（x86_64、emulator-5554）、デバッグ APK | 自動試験（人が補う項目あり） |
| Linux   | 別環境（AppImage / deb）                                    | 人（項目の記載のみ）         |

### 結果欄の凡例

リリース PR の結果表で使う。

| 結果         | 意味                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 未実施       | まだ実施していない（初期値）                                                    |
| OK           | 期待結果どおり                                                                  |
| OK（一部）   | 期待結果どおりだが、確認できたのは一部のみ（備考に未確認の範囲を記載）          |
| NG（要判断） | 期待結果と異なるが、NG とするかどうかの判断が必要（備考に内容を記載）           |
| NG           | 期待結果と異なる（備考に事象・再現手順・ログを記載）                            |
| 対象外       | 環境・データの都合で実施できない（理由を記載。例: HLS のみの動画が無い）        |
| 人が実施     | 自動試験の対象外で、人が実施して結果を記録する（実施後は OK / NG に置き換える） |

### 実施者の区分

- **自動試験可**: Windows 実機・Android エミュレータで自動操作により実施できる（`.claude/skills/autonomous-manual-test` の手順と安全ルールで実施する）。
- **人**: 実機・別環境・目視判断が必要な項目。
- **人（外部影響あり）**: X アカウントへの投稿・いいね・フォロー等、外部に影響する操作。**エージェントは実施しない**。コンポーズは開くだけで投稿しない。

### 優先度

高: リリース可否に直結する / 中: 主要機能の回帰確認 / 低: 補助的な観点。

### 更新試験の手順（W-11 / W-12 / A-30 / A-31 / L-14 向け）

手順の正は `docs/development/updater-test-notes.md`。要点のみ記す（本番リリースは使わない）。

1. `npm run updater-test:setup`（試験用の署名鍵を `tmp/updater-test/keys/` に生成。本番の鍵は使わない）
2. 旧版: `npm run updater-test:build -- --target windows --role old`（Android は `--target android --role old --emulator`）。出力のインストーラ / APK を入れて起動できる状態にする
3. 新版: `npm run updater-test:build -- --target windows --role new --version <現行より大きいバージョン>`（Android は `--target android --role new --version <現行より大きいバージョン> --emulator`）
4. `npm run updater-test:serve`（ポート 8787、`127.0.0.1` / `::1` のみ）
5. 旧版で更新を実行する。異常系は `node scripts/updater-test/server.mjs --bad-digest`（APK ハッシュ不一致）や別鍵で署名した新版（署名不一致）で確認する
6. 注意: 試験用ビルドは本番と同じ identifier で普段使いのインストールと設定を共有し、更新後は GitHub から更新されない。試験後は GitHub Releases から正式版を入れ直す。Android は debug 署名のため、正式版が入っている端末では先にアンインストールが必要

## 4. Android
