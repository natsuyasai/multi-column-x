フロントエンド（React 層）

src/ 配下の React 19 + TypeScript が担う範囲を、外部設計（責務・境界・Rust との接点）と詳細設計（状態管理・カラム管理・各機能・一覧・フロー）に分けて説明します。X の画面に注入されるスクリプトは inject ページを参照してください。

前提知識

このコードベースを読むのに最低限必要なものだけを挙げます。

技術 このプロジェクトでの使われ方
関数コンポーネントとフック クラスは使わない。状態・副作用は useState / useEffect と、自作フック（src/hooks/）に切り出す。effect の宣言順に意味がある箇所は多い。
Zustand 単一ストア useAppStore。React 外（services など）からも useAppStore.getState() で参照する。
Tauri の invoke / listen コマンド名・イベント名は文字列で渡すため、定義元 src/constants/ipc.ts に集約する。
CSS Modules / SCSS *.module.scss をコンポーネントと同じ場所に置く。寸法は rem（後述の規約）。
i18next 文言は t("ns:key") の名前空間付き完全キー。辞書は src/locales/{ja,en}/。
@/ エイリアス @/* は src/* を指す。新規コードは @/ で import する。

外部設計: 責務と境界

フロントエンドの責務

React が描くのはメインウィンドウの UI（ツールバー・各カラムのヘッダー・ダイアログ・設定画面・モバイルのタブバー）と、アプリの状態（アカウント・カラム・設定）の管理です。X の画面そのものは React では描きません。カラムごとに作られる子 WebView（OS ネイティブ）がそれを表示し、React は「どこに置くか」を数値で指示するだけです。

z-index が効かない

子 WebView は DOM の外にあるため、React のダイアログを CSS でどれだけ手前にしても、X の画面が上に表示されてしまいます。そこでダイアログ表示中は全カラムを画面外（x=-9999）へ退避し、閉じたら元に戻します（フローは フロー参照）。新しいダイアログ・ポップアップ系 UI を足すときは App.tsx の anyDialogOpen に条件を足すこと。詳しくは column-layout-notes.md。

Rust との接点（インターフェース）

方向 手段 React 側の置き場
React → Rust invoke(IPC_COMMANDS.XXX, args) src/services/ のラッパー、またはストア（load_settings / save_settings）、一部フック（アカウント系・自動更新など）
Rust → React listen(IPC_EVENTS.XXX, handler) src/hooks/useWebviewEvents.ts に集約。アカウント系は useAccounts、ショートカットは useKeyboardShortcuts
React → カラム WebView eval_in_webview で JS 文字列を実行（WEBVIEW_SCRIPTS が文字列を生成） evalInColumn（services/columnWebview.ts）
カラム WebView → React inject が invoke → Rust が emit → React が listen 下表「購読イベント一覧」

コマンドの全体像は Rust 層ページと tauri-commands.md を参照。コマンド名・イベント名の食い違いは契約テスト（src/constants/ipc.contract.test.ts など）が検出します。

依存の向きは基本的に components → hooks → services / store → lib / constants / types です。lib は Tauri にも React にも依存しない純粋関数で、最も下に置かれます。ノードをクリックすると詳細が開きます。

詳細設計: 状態管理

useAppStore

状態はほぼ src/store/useAppStore.ts の単一ストアに置きます。2 種類に分かれます。

種別 内容
永続化される accounts / columns / globalSettings（settings.json に保存）
揮発 isLoaded / isMobile / topBarExpanded / unreadCounts / apiRateLimits / restoreInProgress / reloadAllSignal など

永続化（settings.json）との同期

  • 起動時に loadSettings() が load_settings を invoke。旧形式のカラムは migrateColumn で gridRow/gridCol を補う。
  • 更新アクション（addColumn / updateColumn / updateGlobalSettings など）は、state 更新の直後に saveSettings() を呼ぶ＝自動保存。保存対象は { accounts, columns, globalSettings } を丸ごと save_settings へ。
  • 保存はモジュール変数 saveChain に連結して直列化。実行時点の最新状態を get() で読むので、連続呼び出しでも最後に書かれるのは最新。 flushPendingSaves() で保存完了を待てる。
  • createColumnWebview は作成前に flushPendingSaves() を待つ（全体設定は Rust が settings.json から読んで WebView へ埋め込むため、保存前の古い値が入るのを防ぐ）。
  • 読み込みに失敗したら settingsSaveBlocked を立てて保存を止める（既定値で保存済み設定を空上書きしないため）。
復元中は保存しない

バックアップ復元中は restoreInProgress が true になり、自動保存・自動更新（useAutoReload）・アカウント追加／再認証が止まります。復元の置換処理（Rust の apply_restore）が書くファイルと競合しないための仕組みです。Rust 側の保存の安全策は settings-file-crash-safety-notes.md。

設定の既定値は Rust の impl Default が唯一の定義で、TS の DEFAULT_GLOBAL_SETTINGS（src/types/index.ts）と contracts/default-settings.json と契約テストで一致を保証します。既定値を変えるときは 3 箇所を同時に更新します。

詳細設計: カラム管理

グリッドと座標計算

カラムは gridRow / gridCol のマトリクスで配置します。同じ gridCol に複数あれば縦積みで、heightMode（auto / fixed）と heightValue / heightUnit が各カラムの高さを決めます。座標計算は純粋関数 calculateGridBounds（src/lib/gridLayout.ts）で、コンテナ高・スクロール量・各種バー高を受け取り Record<columnId, ColumnBounds> を返します。

  • 新規カラムは「既存の最大 gridCol + 1」に置かれる（空きセル探索はしない）。
  • heightMode: "fixed" の合計が溢れる／余るケースは未対応の割り切り仕様（空白になる）。
  • order は後方互換のため残している。

desktop と mobile の差分

useColumns（src/hooks/useColumns.ts）が useDesktopColumns と useMobileColumns を束ねるファサードです。

  • 全カラムを同時に表示。横スクロールは下部のスクロールバー（scrollbarRef）で表現し、WebView を scrollLeft 分ずらして配置。
  • recalculateAllBounds が全カラムの bounds を再計算し resize_column_webview を並列で呼ぶ。
  • リサイズは 100ms デバウンス、スクロールは rafThrottle で間引く。
  • Linux は WebView が独立ウィンドウのため、ウィンドウ移動（onMoved）でも再計算。仕様は linux-column-spec.md。
  • アクティブなカラム（2 カラム表示設定ならその隣も）だけ画面内、他は画面外（OFFSCREEN.MOBILE_X）。
  • setActiveColumn は先に Cookie をアクティブカラムのアカウントへ切替 → 非表示分を並列 resize → 表示分を順に resize（アクティブを最後に）。世代番号で古い呼び出しを打ち切る。
  • アクティブ ID は localStorage に保存し、バックグラウンド復帰で React が再読込されても復元できる。
  • 座標は mobileColumnLayout（lib/gridLayout.ts）に一本化。作成時とリサイズ時で別計算にしない。
  • スワイプバーはネイティブ（Kotlin）のオーバーレイ。React は useMobileSwipeBarSync で状態を同期するだけ。詳細は Android ページ。

ネイティブ bounds と rem

アプリ UI の倍率は <html> の font-size で変えます（useUiScale）。子 WebView は DOM 外なので、TopBar・ヘッダー・スクロールバー・モバイルタブバーの高さは rem 定数（HEADER_HEIGHT_REM など）で持ち、 get*Height() が remToPx で px に変換して bounds に渡します。 SCSS の高さと rem 定数は同じ値に保つ必要があり、 src/lib/gridLayout.contract.test.ts が検証します。倍率変更時の bounds 再計算は dialogOpen effect とは別の effect にしてあり、依存を足して壊さないこと。詳細は ui-scale-notes.md。

設定の埋め込みと WebView の再構築

画像ぼかし・カスタム CSS・広告非表示などは、WebView 作成時に初期化スクリプトへ埋め込まれます。eval や再読み込みでは変わりません。そこで WebView の作成成功時に「埋め込まれる項目だけから作った署名」を記録（columnBuildRegistry）し、現在の設定との差（isColumnBuildStale）で古いカラムだけを再構築します。

操作 反映方法
カラム個別設定の「適用」 当該カラムを必ず再構築（recreateColumnWebview）
全体設定の「適用」 必要な eval を送った上で、古いカラムだけ直列に再構築（recreateStaleColumns）
手動の再読み込み（↺・r キー等） 古ければ再構築、そうでなければ eval による軽量リロード（columnReload.ts）

詳細設計: 各機能

アカウント管理

useAccounts が追加・削除・再認証を管理し、UI は AccountManager / AccountNameDialog。ログイン完了の検出経路が desktop と mobile で異なります。

open_add_account_window はウィンドウを開いて即座に返る。Rust が URL をポーリングしてログイン完了を検出し、 account-login-complete を emit。React は listen してアカウント名入力へ進む。ウィンドウをログイン前に閉じたら delete_account_data で作成済みディレクトリを削除。

open_add_account_window が AddAccount Activity の終了までブロックし、成功なら resolve（キャンセルは reject で何もしない）。 xUserId も戻り値で届く。

アカウント削除時の保存先削除失敗は pendingDataDirectoryDeletions に積み、後で再試行します。再認証の同一性照合は lib/reauthIdentity.ts。詳細は release-theme-reauth-notes.md。

設定パネル

  • SettingsPanel: カラム個別設定。適用で当該カラムを再構築。
  • AppSettingsPanel: アプリ全体設定。タブ（レイアウト・プリセット・バックアップ・拡張機能）とセクション分割。入力中は下書き（settingsDraft.ts）を持ち、「適用」で handleApplyGlobalSettings が保存と反映を行う。
  • 適用処理は useSettingsApplyHandlers に集約（フローは フロー参照）。

ダイアログ群と TopBar / MobileTabBar

ダイアログの開閉は useDialogState で一元管理され、その OR が dialogOpen。App では更新通知・アカウント名入力・レート制限ポップオーバーなども足した anyDialogOpen が WebView 退避の条件です。パネル型ダイアログを新設するときは src/styles/_dialog-fullscreen.scss のミキシンで Android 全画面化します。TopBar は desktop の常設ツールバー（展開で高さが変わり、変化時に bounds を再計算）、MobileTabBar は Android の下部タブです。

キーボードショートカット

useKeyboardShortcuts はメインウィンドウの keydown を扱い、修飾キー無しのもの（r / ?）は入力要素上では無効にします。ダイアログ表示中は disabled。カラム WebView 側で押されたキーは、inject が invoke → Rust が webview-keyboard-shortcut を emit して同じフックが受けます。 ショートカット一覧の表示は ShortcutHelpDialog。

テーマ・UI スケール・言語

  • テーマ: useTheme が解決済みテーマを <html data-theme> に反映（system のときだけ OS 配色を購読）。適用時はカラム側にも night_mode Cookie を eval で反映。配色トークンは src/index.css、白文字を載せる塗り背景は --mcx-accent-fill を使う。
  • UI スケール: useUiScale。デスクトップの auto は 1.0 固定、Android は端末のフォント倍率を測定。useAppBootstrap の直前に呼ぶ。
  • 言語: useAppLanguage が設定に応じて i18next を切替。変更時は開いているカラムの注入 UI の言語も eval で更新。

自動更新

useAppUpdater が createUpdater(isMobile) で desktop（プラグイン）／mobile（APK 自己更新）の実装を切り替えます。起動時チェックはカラム復元完了（columnsRestored）までゲートし、更新ダイアログがネイティブ WebView の裏に隠れるのを防ぎます。「後で」のバージョンは localStorage に記録して再通知を抑制します。

バックアップ / リストア

useBackupFlow（画面状態）→ services/backup.ts（IPC と performRestore）→ Rust の apply_restore。復元手順は 「フラグ設定 → 保存待ち → 置換 → 旧 WebView 破棄 → ストア置換（保存しない）→ WebView 再生成 → フラグ解除」。出力は BackupGlobalSettings のホワイトリスト方式です。詳細は backup-restore-notes.md。

API レート制限表示

inject が X の API 応答ヘッダから読んだ残量を報告し、webview-api-rate-limit を useApiRateLimitReports が受けて apiRateLimits（accountId → bucketKey）へ反映。ApiRateLimitIndicator がポップオーバーで表示します。ポップオーバーの開閉も WebView 退避の対象です。詳細は api-rate-limit-operations-notes.md。

落とし穴・関連資料

よくある落とし穴

  • ダイアログを足したのに WebView が前面に残る → App.tsx の anyDialogOpen に条件を足し忘れている。
  • effect の順序を入れ替えて起動が壊れる → useUiScale → useAppBootstrap、isMobile 確定 → loadSettings の順は仕様。
  • anyDialogOpen の effect に依存を足す → 他の依存で再実行されると退避／復元が暴発する。別 effect にする。
  • 設定を変えたのにカラムに反映されない → 構築時に埋め込む項目は署名（columnBuildSignature）に含める。含めすぎると無駄な再構築になる。
  • SCSS の高さだけ変更 → rem 定数と不一致になり WebView と UI がずれる。契約テストで検出される。
  • 連続リサイズ／スクロールで Linux がクラッシュ → 高頻度の resize_column_webview は rafThrottle で間引く。
  • 新規コマンドの追加 → ACL 3 点（build.rs / capability）の更新が必要。ハウツーを参照。
