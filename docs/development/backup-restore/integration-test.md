# バックアップ／リストア 手動テスト項目

自動テストで確認できない項目（実機の SAF、プラットフォーム間の移行、実 WebView での復元後の表示）をまとめる。自動化済みの範囲は [../backup-restore-notes.md](../backup-restore-notes.md) を参照。

## 前提

- 事前に、復元先の端末で 2 つ以上の X アカウントにログインしておく（バックアップにログイン情報は含まれない）。
- 各項目は desktop（Windows / macOS / Linux のうち確認できるもの）と Android の両方で行う。

## 1. バックアップの作成

- [ ] アプリ設定 →「バックアップ」タブが desktop・Android の両方で表示される。
- [ ] 「バックアップを書き出す」で保存先を選べ、既定名が `multi-column-x-YYYYMMDD.mcxbackup.json` になる。
- [ ] 画面に「このバックアップにはログイン情報は含まれません。復元先で事前にログインしてください」と、共有時の個人情報への注意が表示されている。
- [ ] 保存ダイアログをキャンセルしてもエラーにならない。
- [ ] 書き出したファイルをエディタで開き、Cookie・`dataDirectory`・`createdAt`・`windowBounds`・削除待ち一覧・絶対パスが含まれない。`accounts` は `backupAccountId` / `label` / `color` / `xUserId` のみ。
- [ ] **Android**: SAF の「名前を付けて保存」で任意のフォルダ（内部ストレージ、Google ドライブ等）に保存でき、保存後にファイルアプリから開ける。

## 2. 読み込みの拒否

既存のカラムと設定が変わらないこと、理由が表示されることを確認する。

- [ ] 壊れた JSON（末尾を削ったファイル）→ 「ファイルが壊れているか…」。
- [ ] 別アプリの JSON（`format` を書き換えたファイル）→ 「Multi Column X のバックアップファイルではありません」。
- [ ] `schemaVersion` を 2 に書き換えたファイル → 「アプリを更新してください」を含む案内。
- [ ] 5 MiB を超えるファイル → サイズ超過。
- [ ] `customUrl` を `javascript:alert(1)` にした外部カラムを含むファイル → 拒否。
- [ ] **Android**: 5 MiB 超のファイルを選んでもアプリが固まらず、サイズ超過で拒否される。

## 3. アカウント紐づけ

- [ ] 紐づけ画面の各行に、色・ラベル・「カラム N 件」・復元先の選択（復元先アカウント一覧と「復元しない」）が表示される。
- [ ] 双方に X ユーザー ID があり一致するアカウントが初期選択される。片方でも未設定なら選ばれない。
- [ ] 紐づけが 1 件もない間は「確認へ進む」が押せず、理由が表示される。
- [ ] 同じ復元先を 2 つのバックアップ内アカウントに割り当てると警告が出るが、進める。
- [ ] 復元先に X ユーザー ID 未取得のアカウントがあると「再認証すると自動候補が効く」旨のヒントが出る。
- [ ] 新しく追加したアカウントには X ユーザー ID が保存され、そのアカウントを含むバックアップの読み込みで自動候補になる（desktop・Android）。
- [ ] 既存アカウント（旧バージョンで追加し ID 未保存）が、カラムを持っていれば読み込み時に補完される（desktop）。Android は Profile API 対応端末のみ。

## 4. 復元

- [ ] 確認画面に「復元されるカラム N 件 / スキップ M 件」と全置換の警告（ウィンドウ位置・アカウントは置き換わらない旨）が表示される。確認しないと実行されない。
- [ ] 「復元しない」にしたアカウントのカラムは復元されず、外部カラムは復元される。
- [ ] 復元後、カラムの表示（WebView）が再生成され、紐づけ先アカウントのセッションで表示される（ログイン状態が維持されている）。
- [ ] 復元後もウィンドウ位置・アカウント一覧は変わらない。プリセットと既定アカウントも紐づけに従っている。
- [ ] 復元後にアプリを再起動しても内容が保持されている。
- [ ] `app_data_dir/restore_snapshots/` に `appsettings-日時.json` が作られ、6 回以上復元しても 5 件までに制限される。
- [ ] 復元中は自動更新・アカウント追加・再認証が動かない（復元ボタン押下直後に別操作をしても競合しない）。
- [ ] **Android**: 復元後にカラムの切り替え・スワイプ・タブ表示が正常（`showColumnWebView` の再呼び出し等の追加手順が必要かを確認する。必要なら不具合として記録する）。

## 5. プラットフォーム間の移行

- [ ] Windows / macOS / Linux で作成したバックアップを Android で選択して復元でき、紐づけ画面を経て復元できる。
- [ ] Android で書き出したファイルを PC で同じように復元できる。
- [ ] モバイル専用設定（スワイプバー等）が PC 側でも保持され、アプリの動作に影響しない。

## 6. 失敗時の動作

- [ ] 復元直前の退避に失敗する状況（`restore_snapshots` を同名のファイルで塞ぐ）では復元が行われず、エラーが表示され、既存のカラムと設定が変わらない。
- [ ] WebView の再生成に失敗した場合（再現が難しいためログ確認でよい）、「再起動して確認」と退避フォルダの場所が案内される。

## 7. 非機能

- [ ] ライトテーマ・ダークテーマの両方でバックアップタブの表示が崩れない。
- [ ] Android の OS バックアップ（Auto Backup）の挙動が変わっていない（本機能と独立）。
